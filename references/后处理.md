# 后处理参考

## 视频编码兼容性 (video 模式)

`video` 模式合并时会**自动检测视频流编码**，并做兼容处理：

| 视频流编码 | 处理 |
|-----------|------|
| `h264`/`avc1` | 直接复制合并（无需转码，最快） |
| `hevc`/`av01`（环境有 libx264 或 h264_videotoolbox） | 自动转码为 H.264 + AAC，保证所有设备可播放 |
| `hevc`/`av01`（环境无任何 H264 编码器） | 原样复制 + 提示兼容风险 |

> **编码器优先级：** `libx264`（软件，画质控制好）→ `h264_videotoolbox`（Apple 硬件加速，iOS/macOS 通用）。脚本自动探测可用编码器。

> **为什么有这一步？** B 站部分视频流是 HEVC/AV1 编码，很多**手机自带的播放器黑屏**（解码不支持）。转成 H.264 后任何设备都能播。

> **提示：** 若环境无 libx264（如精简 ffmpeg），可在 macOS 用 `brew install ffmpeg` 或 Linux 用 `apt install ffmpeg` 获得完整编码器，脚本会自动启用转码。

## 转成 mp3

默认下载是 `.m4a`（AAC，无损无损重编码）。如需 MP3（如用于旧设备/剪辑软件），用 ffmpeg：

```bash
ffmpeg -i "输入.m4a" -vn -acodec libmp3lame -q:a 2 "输出.mp3"
```

批量转当前目录所有 m4a：
```bash
for f in *.m4a; do
  ffmpeg -y -i "$f" -vn -acodec libmp3lame -q:a 2 "${f%.m4a}.mp3"
done
```

> 注意：请勿使用 yt-dlp 的 `-x --audio-format` 在 iSH 环境中转码——实测该环境的 ffmpeg 后处理子进程有中文/参数传递 bug，会报 `Error opening input files`。用上面独立 ffmpeg 命令替代。

## 文件命名

脚本默认用 `` %(title)s.%(ext)s ``。
- 提取 m4a 时已是 m4a 后缀
- 若需日期前缀：改 `-o "%(upload_date)s_%(title)s.%(ext)s"`

## 强制覆盖

若目标文件已存在，yt-dlp 默认 `--force-overwrites` 关闭会跳过。如要重下：
```bash
rm -f "目标.m4a"   # 或加 --force-overwrites
```

## 网络/CDN 问题

偶发 `HTTP Error 503`（B站 CDN 快速变动）是正常的，脚本已含 `--retries 8`。若仍反复失败，稍等 30-60 秒重试，或换视频。

## 确认是否下载完整视频时的格式

`video` 模式游客只能到 480p。如需更高，需用户提供已登录 B 站的 cookies（见 SKILL.md 限制说明）。
